Brings back the quiz questions a student got wrong at growing intervals (1 day, then 6 days, then longer), using the SM-2 spaced repetition algorithm, so that what they learned in a course stays learned. Tracks issue [#1047](https://github.com/vicharanashala/vibe/issues/1047).

Reviews are practice only. They never change quiz scores, course progress, HP points or the student's position in the course. The feature is switched off by default and is being built in stages; see the Status section below.

### 🎯 Key Features

- **Seeded from the student's own mistakes.** Every question graded `INCORRECT` or `PARTIAL` in a quiz becomes a review item, due the next day.
- **SM-2 scheduling, exactly as specified in #1047.** A correct answer grows the interval (1 day, 6 days, then the previous interval times the easiness factor); a miss restarts the item at 1 day.
- **Links back to the lesson.** Each item stores the nearest video before the quiz, so the student can rewatch the part that teaches the concept.
- **Graded like the quiz.** Answers go through the same graders as the original quiz (including partial grading settings), but no quiz attempt is created.
- **Safe for quiz submissions.** Scheduling runs after the submission is saved, is not awaited, and never throws.

### 🧑‍🎓 How It Works for a Student

1. The student submits a quiz and gets some questions wrong.
2. From 00:00 IST the next day, those questions appear in their due reviews.
3. They answer each question and say whether they were **sure** or **unsure**.
4. They see whether they were right, the correct answer and its explanation, and when the question will come back.

The student-facing Reviews page, dashboard card and reminders are planned for the next stages. Until then the feature is available through the API only.

### 🧬 Data Model

One document per student, question and course version in the `reviewItems` collection (`IReviewItem`):

| Field | Meaning |
|---|---|
| `userId`, `courseId`, `courseVersionId`, `cohortId?` | Owner and scope |
| `questionId`, `quizId` | The question and the quiz it was missed in |
| `source` | `QUIZ_MISS` now; `BANK_TOPUP` is reserved for the course-completion top-up |
| `relatedVideo?` | `{moduleId, sectionId, itemId}` of the video before the quiz |
| `repetitions`, `easeFactor`, `intervalDays` | SM-2 state `n`, `EF`, `I` |
| `nextReviewAt`, `lastReviewedAt?`, `lastQuality?` | Scheduling and the last result |
| `reviewCount`, `lapses` | How often it was reviewed, and how often missed in a review |
| `status` | `ACTIVE` or `RETIRED` |

Indexes: a unique index on `(userId, courseVersionId, questionId)`, so missing a question again restarts the existing item instead of adding a duplicate, and `(userId, status, nextReviewAt)` for due-review queries.

**Recall quality** (`toRecallQuality`), following the issue's *Got it / Unsure / Missed it* = 5 / 3 / 1 mapping:

| Graded answer | Sure | Unsure |
|---|---|---|
| Correct | 5 | 3 |
| Partly correct | 2 | 2 |
| Incorrect | 1 | 1 |

**SM-2** (`applySm2`), with the issue's rule that a miss leaves `EF` unchanged:

```text
if quality >= 3:
  interval = n == 0 ? 1 : n == 1 ? 6 : round(interval * EF)   # EF from before this review
  n = n + 1
  EF = max(1.3, EF + (0.1 - (5 - q) * (0.08 + (5 - q) * 0.02)))
else:
  n = 0, interval = 1
nextReviewAt = start of the IST day, `interval` days after the review
```

Example: a student who always answers *Got it* sees a question again on days 1, 7, 23, 68 and 199.

**Which questions are used** (`isReviewableQuestion`): single choice, multiple choice, ordering and numeric questions that are not parameterised, not student-generated and not awaiting review. Descriptive questions are left out because they are not auto-graded.

### 🔌 API

Both routes need a signed-in student and only ever act on the caller's own items. They return 404 while `ENABLE_SPACED_REPETITION` is off.

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/reviews/due?courseVersionId=&limit=` | Due reviews, oldest first (default 20, maximum 50). Each question is rendered as in a quiz, without answers or option explanations. |
| `POST` | `/reviews/:reviewItemId/answer` | Body `{questionType, answer, confidence: "SURE" \| "UNSURE"}`. Grades the answer, reschedules the item and returns `status`, `quality`, `correctAnswer`, `intervalDays`, `nextReviewAt` and `relatedVideo`. |

Answering a review that is not due yet returns 400, as does an answer for the wrong question type or of the wrong shape.

### ⚙️ Configuration

| Variable | Default | Effect |
|---|---|---|
| `ENABLE_SPACED_REPETITION` | `false` | Schedules reviews from quiz misses and enables the review routes |
| `ENABLE_SPACED_REPETITION_JOB` | `false` | Reserved for the daily reminder job (not built yet) |

### 🔁 Workflow

1. **Quiz submitted.** `AttemptService.submit` saves the grading result, then calls `ReviewSeedingService.seedFromQuizGrading` without awaiting it. The dependency is injected as optional, so containers built without this module still create `AttemptService`.
2. **Seeding.** The service loads the missed questions in one query, keeps the reviewable ones, finds the related video with `ProgressService.getPreviousVideoItem`, and upserts one item per question due tomorrow. Any error is logged and swallowed.
3. **Listing due reviews.** `ReviewService.getDueReviews` loads each question with `getByIdWithoutExplanation` and renders it with `QuestionProcessor`, skipping questions that were deleted or became unsuitable.
4. **Answering.** `ReviewService.answerReview` checks ownership and that the item is due, grades with `QuestionProcessor.grade` against the original quiz, applies SM-2 and saves the result with `ReviewItemRepository.recordReview`.

### ⚠️ Known limitations

- **API only for now.** There is no student page until stage 3.
- **No reminders yet.** Students are not notified about due reviews until stage 4.
- **Descriptive, parameterised and crowd-sourced questions are not reviewed** in this version.
- **A question changed by the instructor** is reviewed in its current form; a question that was deleted is skipped.
